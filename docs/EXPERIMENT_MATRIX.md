# Classifier experiment matrix (v2)

The v2 matrix is additive to, and independent of, the original 22-experiment
`configs/final_classifier_registry.json` pipeline: it never edits that registry, its notebooks
(`01a`-`04c`), or its lock (`results/final_evaluation/FINALISTS_LOCKED`). It lives under its own
namespace (`experiments/classifiers_matrix/`, `results/classifiers_matrix/`,
`results/final_evaluation_v2/`) so both pipelines can coexist.

## Dataset variants

`configs/dataset_variant_registry.json` is generated by
`notebooks/utility/dataset_variant_registry.py` from three sources only: generator identity from
`configs/final_generator_registry.json`, real/augmented train-side counts from
`data/processed/metadata/train.csv` and `data/real_augmented/`, and per-generator synthetic
counts resolved from each generator's own metrics file (never hand-typed). Re-running the builder
recomputes everything from those sources; nothing here is a manual edit.

As of the last build against this repository: 28 Stage 1 variants (`R`, `RA`, per-generator
`RSB_CONTROLLED_*` / `RSB_FULL_*` / `RSP_CONTROLLED_*` for the 7 two-class generators,
`RSP_CONTROLLED_G05` / `RSP_FULL_G05`, and 3 legacy-compatible variants —
`RS_PARTIAL_G02`, `RS_FULL_G02`, `SYNTHETIC_ONLY_PARTIAL_G02` — cross-referenced from real entries
in `final_classifier_registry.json`; `SYNTHETIC_ONLY_FULL_G02` is not emitted because no matching
full-fine-tuning synthetic-only experiment exists yet). `COMMON_SYNTHETIC_PER_CLASS` and
`COMMON_SYNTHETIC_POSITIVE` both resolved to 1361 (the binding constraint is G01/G02/G03/G06/G07/G08's
validated filtered count; G04's LoRA set is larger at 2722 and is only fully used in
`RSB_FULL_04_sd21_lora`).

Stage 2 variants (`RAS_*`, `S_ONLY_*`) are not pre-populated: `build_stage2_variants()` only
builds them for generators inside a signed `SELECTED_GENERATOR_UNION`
(`results/generator_comparison/selected_generator_union.json`), produced by
`scripts/finalize_validation_stage.py --stage 1` from validation PR-AUC only.

## Training protocols

`configs/classifier_training_protocols.json` has one policy per architecture (ResNet-50 on
Keras/TensorFlow with its existing two-phase head-then-partial-finetune schedule; MaxViT-512,
Mammo-FM and RAD-DINO on PyTorch), each pinned to the real hyperparameters already used by
`notebooks/utility/maxvit_utils.py` / `mammofm_utils.py` / `medfoundation_utils.py` and the
ResNet notebooks where those were determinable. `max_optimizer_updates` is the primary training
budget (spec requirement); the runner is responsible for translating it into an epoch count for
whatever dataset variant it is training on, not the policy file itself.

## Jobs

`scripts/build_classifier_experiment_matrix.py --stage {1,2}` writes
`configs/classifier_experiment_matrix.json`: one job per (architecture, dataset_variant, seed in
{17, 42, 73}). Rebuilding never resets progress — every job's `status` is reconstructed from
on-disk artifacts (`notebooks/utility/classifier_run_manifest.py`), not blindly set to `PENDING`.
States: `PENDING, CLAIMED, RUNNING, TRAINED, VALIDATED, COMPLETE, BLOCKED, FAILED_RETRYABLE,
FAILED_FINAL, INVALIDATED`.

Stage 1 against the current registry produces 336 jobs (4 architectures x 28 variants x 3 seeds).

## Legacy checkpoint reuse

`notebooks/utility/classifier_checkpoint_io.legacy_alias_for()` looks up
`dataset_variant["legacy_experiment_ids"]` (populated only for the three cross-referenced legacy
variants above) against `final_classifier_registry.json` by architecture, so the runner can skip
retraining a combination that already has a verified legacy checkpoint. It never guesses a
mapping for variants without an explicit, evidence-backed cross-reference.

## Operational order

1. `python scripts/build_classifier_experiment_matrix.py --stage 1`
2. `python scripts/profile_classifier_vram.py`
3. `python scripts/run_classifier_experiment_matrix.py --stage 1 --mode auto --target-5060-jobs 3 --target-3060-jobs 2`
4. `python scripts/status_classifier_experiment_matrix.py --watch` / `python scripts/resume_classifier_experiment_matrix.py --stage 1` as needed
5. `python scripts/finalize_validation_stage.py --stage 1` (writes and signs `SELECTED_GENERATOR_UNION`)
6. `python scripts/build_classifier_experiment_matrix.py --stage 2 --selected-union results/generator_comparison/selected_generator_union.json`
7. repeat 3-4 for stage 2, then `python scripts/finalize_validation_stage.py --stage 2`
8. `python scripts/finalize_locked_test_stage.py` (reports readiness only), then, only when ready and intended,
   `python scripts/finalize_locked_test_stage.py --confirm-locked-test`
9. real-run `04y_v2_Final_Test_Locked_Matrix.ipynb`, then `04z_v2_Final_Statistical_Comparison_Matrix.ipynb`

Steps 8-9 are the only steps that touch the test set, and only after every earlier step is
complete and the lock signature has been written.
